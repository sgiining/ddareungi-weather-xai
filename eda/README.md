# eda/ — 탐색 분석 (모델링 전 점검)

모델을 만들기 전에 데이터를 직접 계산해 확인하고, 그 결과를 근거로 설계를 정하기 위한 폴더입니다.
여기서 나온 수치와 판단만 연구계획서에 씁니다.

## 이 폴더에서 확인하는 것

| 번호 | 스크립트 | 확인하는 질문 | 결과로 정하는 것 |
|---|---|---|---|
| 1 | `01_check_blanks.py` | ASOS 강수·적설 빈칸이 정말 "비·눈 없음"인가? | build_dataset.py의 0 채우기를 유지할지 |
| 2 | `02_describe_data.py` | 변수별 범위·평균·빈칸 수, 공휴일·쉬는 날 수, 단계별 일수 | 계획서 4.1 Dataset 절의 수치 |
| 3 | `03_level_change.py` | 연도별 대여 수준이 달라졌는가? (같은 달끼리, 평일·비 없는 날끼리 비교) | 계획서 4.1·5절 서술, ME·보조 실험의 필요성 |
| 4 | `04_weather_correlation.py` | 날씨 후보 10개 중 서로 거의 같은 정보를 담은 쌍이 있는가? | 함께 넣지 않을 변수 후보 |
| 5 | `05_compare_feature_sets.py` | 변수 조합을 바꾸면 조정 단계(2023→2024) 오차가 얼마나 달라지는가? | 최종 날씨 변수 |
| 6 | `06_plots.py` | 일별 추이, 기온·강수·요일별 평균 대여량 | 계획서 4.1절 그림 |

## 지켜야 할 원칙

- 변수 선택(4·5번)과 관계 그림(6번)은 **2023~2024년 자료만** 씁니다. 시험 A(2025)·시험 B(2026 상반기)를 보고 설계를 바꾸면 결과가 부풀려지기 때문입니다.
- 3번(수준 변화)은 전체 기간을 보지만, 그 결과로 모델 설정을 바꾸지 않습니다. 계획에 이미 있는 ME 지표와 "직전 12개월 학습" 보조 실험으로 다룹니다.
- 5번의 선택 규칙은 **결과를 보기 전에** `DECISIONS.md`에 먼저 적습니다.

## 실행 방법

프로젝트 폴더(`D:\xai\ddareungi-weather-xai`)에서 실행합니다. 먼저 `py build_dataset.py`로 `data/processed/dataset.csv`가 있어야 합니다.

```
py -m pip install scikit-learn matplotlib
py eda/run_all.py
```

- 전부 실행하고 결과를 `eda/results/EDA_REPORT.md` 한 파일로 모읍니다.
- 하나만 다시 실행할 때: `py eda/04_weather_correlation.py` (보고서를 다시 모으려면 `run_all.py`를 다시 실행)
- 5번은 랜덤 포레스트를 35번 학습하므로 CPU에서 몇 분 걸릴 수 있습니다.

## 결과 파일

```
eda/results/
├─ EDA_REPORT.md      ← 전체 결과를 한 번에 보는 파일 (자동 생성, VS Code 미리보기: Ctrl+Shift+V)
├─ sections/          ← 보고서의 각 절 (자동 생성)
├─ tables/            ← 모든 표 (CSV, 엑셀로 열림)
└─ figures/           ← 모든 그림 (PNG)
```

## 기록 방법

- **자동 결과**: `results/EDA_REPORT.md` — 코드가 만든 사실만 담깁니다. 직접 고치지 않습니다.
- **사람의 판단**: `DECISIONS.md` — 결과를 보고 무엇을 결정했는지, 왜 그랬는지 직접 적습니다.
- 계획서에는 `DECISIONS.md`에 적은 결정과 `EDA_REPORT.md`의 수치를 근거로 씁니다.
